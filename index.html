    How I build

    AI is part of the workshop, not the author of the outcome.

    I use it to move faster through implementation and exploration. I still read the code, trace errors, test behaviour and decide what ships.

    Make the shape clear.

    Start from the problem, the person using it, and the smallest useful outcome. That keeps an experiment from becoming a pile of features.

    • Clarify the user action
    • Choose observable success
    • Make the first release narrow

    Build, inspect, adjust.

    Use APIs, automation and AI-assisted workflows where they help - then validate assumptions, label prototypes honestly, and fix what the software actually does.

    • Review generated code
    • Test real inputs and failures
    • Keep claims tied to evidence
