    How I build

    AI is part of the workshop, not the author of the outcome.

    I use AI-assisted tools to move faster through implementation and exploration. I still read the code, trace errors, test behaviour, and decide what actually ships.

    Make the shape clear.

    Start from the problem, the person using it, and the smallest useful outcome. That keeps an experiment from becoming an unfocused pile of features.

    • Clarify the primary user action
    • Choose observable, verifiable success
    • Make the first release narrow and robust

    Build, inspect, adjust.

    Use APIs, automation, and AI-assisted workflows where they help — then validate assumptions, label prototypes honestly, and fix what the software actually does.

    • Review all generated code line by line
    • Test real inputs, edge cases, and failure modes
    • Keep all technical claims tied strictly to evidence
